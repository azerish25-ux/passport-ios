# PassportProof — release and App Store checklist

This checklist separates what the repository can prove from what only the Apple
Developer account owner can complete. A green CI run does not equal a signed or
accepted App Store submission.

## 2. Account-owner work before submission

### Signing and identifiers

1. Register the explicit App ID `com.passportproof.app` in Certificates,
   Identifiers & Profiles.
2. Create the app record in App Store Connect with the same bundle ID.
3. Select the Apple Developer team in Xcode or pass `DEVELOPMENT_TEAM` to
   `xcodebuild`.
4. Increment `CURRENT_PROJECT_VERSION` for every uploaded build. The checked-in
   project value `1` is the first build only.

### In-app purchase

1. Create one **non-consumable** product with identifier
   `com.passportproof.app.unlock`.
2. Add the localized display name and description. Set the price to the product
   decision (the repository's StoreKit test configuration uses US `$17.99`).
3. Attach the purchase to the first submitted app version.
4. Test on a sandbox Apple Account: purchase, cancellation, pending/Ask to Buy,
   restore, offline launch after purchase and revocation handling.
5. Do not submit while Release still displays a Store unavailable state because
   the product has not propagated.

### App Store Connect metadata

- **Privacy policy URL:** required. Ready-to-host policy text is in
  [`PRIVACY.md`](PRIVACY.md); App Store Connect also requires a publicly
  reachable web URL, so publish it on a maintained site or GitHub Pages.
- **Support URL:** required; use a maintained page with a contact method.
- **Category:** Utilities. **Age rating:** 4+ unless future content changes it.
- **App Privacy:** Data Not Collected, no tracking. This must match the bundled
  manifest and the StoreKit-only network surface.
- **Screenshots:** capture marketing images from the current build. CI's
  `simulator-screenshots` artifact supplies evidence, not necessarily final
  marketing composition. Include Library, document detail, capture sources,
  a real diagnosis and export.
- **Review notes:** explain that analysis is informational, the issuer makes the
  final decision, photos are processed on device, and the simulator has no
  camera. Provide reviewer steps using a portrait selected through the system
  photo picker.
- **Export compliance:** the plist already answers no non-exempt encryption.
- **Content rights:** all app artwork and generated brand assets are original.

### Device and print QA

Run [`MANUAL-QA.md`](MANUAL-QA.md) on a physical iPhone before submission. The
simulator cannot prove camera orientation, live gate behavior, permission
recovery, performance on large photos, or printer scaling. A successful
build/test run is not evidence for those.

## 3. Archive and export

Generate the project, then archive with the team selected:

```bash
python3 Tools/generate_project.py
xcodebuild archive \
  -project PassportProof.xcodeproj \
  -scheme PassportProof \
  -configuration Release \
  -destination 'generic/platform=iOS' \
  -archivePath build/PassportProof.xcarchive \
  DEVELOPMENT_TEAM=<TEAM_ID> \
  CODE_SIGN_STYLE=Automatic \
  CURRENT_PROJECT_VERSION=<UNIQUE_BUILD_NUMBER>

xcodebuild -exportArchive \
  -archivePath build/PassportProof.xcarchive \
  -exportPath build/export \
  -exportOptionsPlist ExportOptions.plist
```

`ExportOptions.plist` is checked in for an App Store Connect export with
automatic signing and symbols. Upload the resulting `.ipa` with Xcode Organizer
or `xcrun altool` using an App Store Connect API key. Wait for processing, add
the build to the version, complete export compliance/privacy answers and submit
for review.

## 4. Honest open limitations

- The live camera gate must still be verified on a physical device.
- Print fidelity must be measured on real printers using the calibration sheet.
- Expression, glasses, recency and original-source status rely on explicit user
  confirmation; they are not classifiers.
- Background, shadow, centring and crown-contrast tolerances are app-selected
  thresholds, labelled as such, not issuer-published numbers.
- Only three US workflows are supported. No UK output is offered because a
  single crop/export cannot satisfy both its printed and digital rules.
- A hosted privacy policy and support page do not exist in this repository.
- Signing, TestFlight acceptance and App Review are external and unproven here.
